# RAG 推荐算法与测试教训总结

## 1. RAG 推荐算法概述

桌面宠物推荐功能采用本地 RAG 思路，根据用户输入的学习需求，推荐合适的口语练习场景和词汇练习难度。

当前不接入大语言模型，核心方式是：

```text
数据库内容 / 本地别名配置 -> 构建本地向量索引 -> 用户输入向量化 -> 相似度匹配 -> 返回推荐结果
```

## 2. 数据来源

口语场景来自数据库表：

```text
speaking_scenarios
```

主要使用字段：

```text
id、title、description、summary、goal、keywords、sampleDialogue
```

同时维护本地场景别名文件：

```text
backend/src/main/resources/pet-speaking-aliases.json
```

用于补充中文自然表达和英文场景描述之间的语义映射，例如：

```text
生病 / 看病 / 国外生病 -> 医院就诊
打电话 / 业务电话 / 国外用户 -> 电话沟通
对接业务 / 客户沟通 -> 商务会议
```

词汇等级基于系统已有四个练习入口：

```text
starter      入门
basic        基础
intermediate 中级
advanced     进阶
```

并结合数据库词汇表 `vocabulary` 中的 tag 进行归类：

```text
starter      -> zk, gk
basic        -> cet4
intermediate -> cet6
advanced     -> ky, toefl, gre, ielts
```

## 3. 向量索引构建

系统会生成本地持久化索引文件：

```text
backend/var/pet-vector-index.json
```

构建时，将口语场景文本、场景别名、词汇等级画像和词汇样本转换为 TF-IDF 向量。

重要字段会提高权重，例如：

```text
keywords、场景别名、summary、goal
```

这样可以增强关键意图词对推荐结果的影响。

## 4. 用户输入匹配流程

用户输入后，系统执行以下步骤：

```text
用户文本
  ↓
分词与停用词过滤
  ↓
使用索引中的 IDF 权重生成用户 TF-IDF 向量
  ↓
分别与口语场景向量、词汇等级向量计算余弦相似度
  ↓
取相似度最高的结果作为推荐
```

匹配结果包括：

```text
口语场景 Top1
词汇等级 Top1
相似度分数
推荐跳转路径
```

## 5. 当前方案特点

优点：

```text
实现轻量
不依赖外部 API
可离线运行
索引文件可检查、可迁移
推荐结果可解释
```

局限：

```text
本质仍依赖词面匹配
别名覆盖不足时容易漏匹配
对自然语言泛化能力弱于 embedding
```

例如：

```text
我在 Amazon 买了一本新书，但不是很满意
```

如果别名中没有“买书、网购、Amazon、不满意、售后、退款”等表达，就可能无法准确匹配到购物退换货场景。

## 6. 是否接入 Embedding

Embedding 能提升语义匹配能力，适合处理同义表达和隐含意图，例如将“买书不满意”匹配到“购物退换货”。

但接入 embedding 会增加：

```text
模型或 API 依赖
网络和费用成本
索引版本管理
失败重试和缓存处理
部署复杂度
```

因此当前阶段适合采用：

```text
TF-IDF + 本地别名 + 本地持久化索引
```

如果后续追求更强泛化能力，再升级为：

```text
Embedding + 本地向量索引 / 向量数据库
```

## 7. 测试与实现教训

1. 推荐系统不能只依赖数据库原始字段。  
   数据库中的英文描述和用户中文输入之间存在表达差异，需要补充别名或语义映射。

2. 词汇等级不能只靠词条样本匹配。  
   需要为每个等级建立明确画像，否则“英语很好、缺少专业词汇”这类能力描述可能被误判为低难度。

3. 本地向量索引需要版本管理。  
   算法或字段变化后，旧索引必须自动失效或手动重建，否则会继续使用过期推荐结果。

4. 性能测试应拆分接口统计耗时。  
   只看完整链路总耗时无法定位瓶颈，应分别统计登录、获取题目、提交结果、完成进度等接口的平均耗时、P90、P95 和失败率。

5. 平均响应时间不足以说明稳定性。  
   P95、最大耗时和失败率更能反映高并发下的真实用户体验。

6. 口语测试不适合直接高并发压测。  
   口语链路涉及 ASR、智能回复、TTS、发音评测等外部 API，更适合先做低并发链路验证，再单独评估外部依赖耗时。

7. Mock 数据和真实数据库数据要区分清楚。  
   推荐效果必须基于真实数据库场景验证，否则容易出现前端 mock 命中、真实后端不命中的问题。
